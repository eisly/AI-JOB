### [2026-11-14] P0 批次整改：任务回调序号冲突、投递一致性、题库隔离、搜索来源与账号隔离

**任务目标：**
修复验收标准中的 P0 项：A01（异步回调事件序号冲突）、P01-P03（投递重复添加与日期状态矛盾）、T01-T03（fake 题隔离、题干去重、"不会"进待复习）、S01/S06（搜索前来源状态展示、账号切换隔离）。

**执行行为：**

1. A01 序号冲突：定位到 `TaskResultService.submit` 中 `syncTask`（DB MAX+1 分配）在前、`appendEvent`（内存旧快照+1）在后的分配基准不一致，短任务回调必然触发 `uk_task_id_seq` 唯一键冲突并整体回滚，Agent 重试也无法自愈。修复为 `appendEvent` 统一改用 `nextEventSeq`（DB MAX+1）；`AgentEventSyncService.syncTask` 用 `TransactionTemplate` 包裹"锁定任务行 + 存在性检查 + 序号分配 + 插入"，消除定时器线程与回调线程的并发窗口（回调线程加入外层事务，定时器线程等行锁后凭 `agentEventExists` 幂等跳过）。
2. A03 终态显示：任务中心抽屉与面试页的连接标签在终态后不再显示"轮询恢复中"，改为"已结束"。
3. A05/U09 阶段中文化：`format.ts` 新增 `taskStageLabels`（覆盖 Java 侧 QUEUED/AI_RUNNING/DONE/FINISHED 与 Agent 侧全部 stage 事件名），任务列表与 TaskStatus 组件使用中文阶段标签。
4. P01 重复添加：`ApplicationServiceImpl.create` 对同一用户同一岗位的既有记录返回 409（error.key=DUPLICATE_APPLICATION，details 携带 existingCount）；DTO 新增 `confirmDuplicate`，用户明确确认后创建独立新记录。前端 `ApplicationForm` 捕获该错误弹确认框，确认后带 `confirmDuplicate=true` 重交。
5. P02 日期状态一致性：create 与 update 均校验"待投递状态不得携带实际投递日期"（回退到 PLANNED 时必须同时清空 appliedDate，否则 400 指引）；前端表单状态联动（PLANNED 时禁用并清空实际投递日期）。
6. T01 fake 题隔离：Flyway V12 迁移为 `question` 表加 `generation_env`（默认 PROD）、`user_mistake` 表加 `cause`（默认 WRONG_ANSWER）；Agent 生成题输出携带 `modelProvider`，Java 落库时含 "fake" 的提供方标记 FAKE；候选题查询 `questionCandidates` 排除 FAKE，真实用户不再收到 fake 模板题。
7. T02 题干去重：`LearningQuestionPayload` 新增 `excludedQuestionStems`（Java 侧传已用题干）；Agent 选题时按归一化题干（去空白+小写）排除等价候选，生成新题时校验题干不与已用题干等价，重复则要求换考查角度。
8. T03 "不会"分类：`_build_evaluation` 区分明确"不会"（命中 UNUSABLE_ANSWERS → answerClass=UNKNOWN）与无效回答（过短 → answerClass=INVALID）；Java evaluate 对 UNKNOWN 写入错题本（cause=UNKNOWN，进入待复习与弱项推荐），不伪造分数、不计技能证据；错题本前端按 cause 显示"不会 · N 次"与"错误 · N 次"。
9. S01 来源状态：前端接入孤儿端点 `GET /api/v1/job-searches/source-health`，搜索页新增"来源状态（配置检查）"折叠区，展示各来源三态（未配置/已配置-检索时验证/暂未接入）、最近检测时间与可操作提示；明确标注"配置检查不代表已联网验证"。
10. S06 账号隔离：`JobSearchView` 的搜索/任务恢复 key 与 `task-registry` 的任务提交记录 key 均追加用户 ID 后缀，切换账号后不再读取旧账号的搜索 ID 与重试记录（后端 userId 鉴权原本可防数据泄露，此修复消除前端脏报错状态）。
