## 粘贴个人目标JD并解析

**接口地址**：`/api/v1/jobs/imports`

**请求方式**：`POST`

**请求数据类型**：`application/json`

**响应数据类型**：`application/json`

**接口描述**：创建仅本人可见的USER_INPUT岗位和JD分析任务；不抓取sourceUrl内容。

**权限**：用户。

**请求示例**：

```json
{
  "title": "Java 后端开发",
  "companyName": "星河科技（虚构）",
  "jdText": "本科及以上学历，2026至2027届，熟悉Java、MySQL和Redis；工作内容为业务接口开发。",
  "sourceUrl": "https://jobs.example.invalid/java-001"
}
```

**请求参数**：

| 参数名称 | 参数说明 | 请求类型 | 是否必须 | 数据类型 | schema |
| --- | --- | --- | --- | --- | --- |
| Authorization | Bearer 用户accessToken | header | true | string |  |
| title | 职位名称≤100 | body | true | string |  |
| companyName | 公司名称≤100 | body | true | string |  |
| jdText | 50..30000字符 | body | true | string |  |
| sourceUrl | 可选来源线索；不是可信认证 | body | false | uri? |  |
| Idempotency-Key | UUID；同键同体24小时重放原结果，同键异体409 | header | true | uuid |  |

| 状态码 | 说明 | schema |

| 202 | 任务已受理；不表示结果成功 | CommonResult&lt;TaskVO&gt; |

| 参数名称 | 参数说明 | 类型 | schema |

## 创建匹配任务

**接口地址**：`/api/v1/job-matches`

**请求方式**：`POST`

**请求数据类型**：`application/json`

**响应数据类型**：`application/json`

**接口描述**：传入 `resumeVersionId` 和单个 `jobIds` 时，按本人已解析简历的原文与指定岗位对比，并保留历史。普通匹配使用确认画像；无 `jobIds` 时选择默认可信岗位。

**权限**：用户。

**请求示例**：

```json
{
  "expectedProfileVersion": 3,
  "resumeVersionId": "20000000-0000-4000-8000-000000000001",
  "jobIds": [
    "30000000-0000-4000-8000-000000000001"
  ]
}
```

**请求参数**：

| 参数名称 | 参数说明 | 请求类型 | 是否必须 | 数据类型 | schema |
| --- | --- | --- | --- | --- | --- |
| Authorization | Bearer 用户accessToken | header | true | string |  |
| expectedProfileVersion | 当前画像版本 | body | true | integer |  |
| jobIds | 显式目标≤20；使用指定简历对比时只接受一个岗位；私有 JD 必须本人所有 | body | false | uuid[] |  |
| resumeVersionId | 对比使用的本人简历版本，状态为 PARSED 或 CONFIRMED，且需有原文 | body | false | uuid |  |
| includeUnknown | 是否返回资格待确认项，默认true | body | false | boolean |  |
| Idempotency-Key | UUID；同键同体24小时重放原结果，同键异体409 | header | true | uuid |  |

**响应状态**：

| 状态码 | 说明 | schema |
| --- | --- | --- |
| 202 | 任务已受理；不表示结果成功 | CommonResult&lt;TaskVO&gt; |
| 400 / 401 / 403 / 404 / 409 / 429 / 500 | 详见公共错误码 | CommonError |

**响应参数**：

| 参数名称 | 参数说明 | 类型 | schema |
| --- | --- | --- | --- |
| code | 业务码，200成功/202受理 | integer |  |
| msg | 提示信息 | string |  |
| data | 业务数据 | TaskVO | TaskVO |
| traceId | 关联排障ID | string |  |
| &emsp;id | 任务ID | uuid |  |
| &emsp;type | 见任务类型枚举 | string |  |
| &emsp;status | 见任务状态机 | string |  |
| &emsp;stage | 展示阶段 | string? |  |
| &emsp;progress | 0..100，未知为null | integer? |  |
| &emsp;resourceId | 关联资源 | uuid? |  |
| &emsp;result | 成功时{resourceType,resourceId,version}，其他null | object? |  |
| &emsp;error | 失败时{code,message,retryable}，其他null | object? |  |

## 订阅任务事件

**接口地址**：`/api/v1/tasks/{taskId}/events`

**请求方式**：`GET`

**请求数据类型**：无请求体。

**响应数据类型**：`text/event-stream`。

**接口描述**：仅任务所有者订阅。训练评价等只发stage事件；面试生成可发delta。只有Java事务提交后才发done。所有事件的字段、重连和错误处理见[公共SSE协议](../数据模型、数据库设计与联调约定.md)。

**请求示例**：

```http
GET /api/v1/tasks/70000000-0000-4000-8000-000000000001/events HTTP/1.1
Authorization: Bearer <access-token>
Accept: text/event-stream
Last-Event-ID: 8
```

**请求参数**：

| 参数名称 | 参数说明 | 请求类型 | 是否必须 | 数据类型 | schema |
| --- | --- | --- | --- | --- | --- |
| taskId | 本人任务ID | path | true | uuid | — |
| Authorization | 用户Bearer令牌；禁止URL传token | header | true | string | — |
| Last-Event-ID | 最后已处理的任务内seq，首次缺省0 | header | false | integer | — |

**响应状态**：

| 状态码 | 说明 | schema |
| --- | --- | --- |
| 200 | 成功建立流，不等于任务成功 | TaskEvent |
| 401 / 404 / 429 | 建流前权限、资源或连接限制错误 | CommonError |
| 410 | 历史事件已过期；先查任务状态 | CommonError |

**响应参数**：

| 参数名称 | 参数说明 | 类型 | schema |
| --- | --- | --- | --- |
| id | 任务内单调seq，与data.seq一致 | integer | — |
| event | accepted / stage / delta / done / error / cancelled | string | — |
| data.taskId | 当前任务 | uuid | — |
| data.seq | 去重游标 | integer | — |
| data.payload | 按事件类型判别，见公共协议 | object | TaskEvent |

**响应示例**：

```text
id: 9
event: delta
data: {"taskId":"70000000-0000-4000-8000-000000000001","seq":9,"payload":{"text":"请介绍项目中的缓存设计"}}

id: 10
event: done
data: {"taskId":"70000000-0000-4000-8000-000000000001","seq":10,"payload":{"resourceType":"INTERVIEW","resourceId":"60000000-0000-4000-8000-000000000001","version":3}}

```

浏览器采用fetch读取流以发送Authorization和Last-Event-ID；原生EventSource不支持自定义Authorization请求头，不采用URL令牌。不要将SSE示例写成JSON数组。
