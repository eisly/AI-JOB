# 语音模拟面试 - 回滚与临时数据清理

> 对应迁移：`V17__add_voice_interview.sql`
> 合并后 V15 和 V16 用于项目实战。若某数据库已经执行语音分支原来的 V15，请先核对该库的 Flyway 历史和语音表结构，再制定迁移方案。
> 设计基线：`.codeartsdoer/specs/voice_interview/design.md` 2.3.2「惰性过期与清理」
> 说明：本手册用于运维排障与回滚演练。生产回滚必须由 DBA 在变更窗口执行，**不提供自动回滚**。

当前分支提供 Mock 语音能力。默认 `AGENT_SPEECH_PROVIDER=auto` 在开发和测试环境使用 Mock，在生产环境关闭语音路由。真实 Provider 上线前，生产 Java 后端应将 `APP_VOICE_ASR_ENABLED` 和 `APP_VOICE_TTS_ENABLED` 均设为 `false`。

## 1. 回滚顺序（必须按依赖逆序）

```sql
-- 1) 同意表（依赖 app_user）
DROP TABLE IF EXISTS `interview_voice_consent`;

-- 2) 转写表（依赖 app_user / interview_session / interview_message）
DROP TABLE IF EXISTS `interview_voice_transcription`;

-- 3) 消息来源：先删 CHECK，再删列
ALTER TABLE `interview_message` DROP CHECK `ck_interview_message_source_role`;
ALTER TABLE `interview_message` DROP CHECK `ck_interview_message_source`;
ALTER TABLE `interview_message` DROP COLUMN `answer_source`;

-- 4) 会话模式：先删 CHECK，再删列
ALTER TABLE `interview_session` DROP CHECK `ck_interview_session_mode`;
ALTER TABLE `interview_session` DROP COLUMN `mode`;
```

注意：

1. 回滚会丢失语音来源标记与未消费的候选转写文本；已提交的正式回答文本保存在 `interview_message.content`，不受影响。
2. 回滚前建议先导出 `interview_voice_transcription` 中 `status='SUCCEEDED' AND consumed_at IS NOT NULL` 的行，便于排障追溯。
3. 回滚后 `interview_message` 与 `interview_session` 的历史数据语义恢复为纯文字面试。

## 2. 临时转写清理（日常运维）

### 2.1 未消费且过期超过 24 小时

```sql
DELETE FROM `interview_voice_transcription`
WHERE `expires_at` < UTC_TIMESTAMP(3) - INTERVAL 24 HOUR
  AND `consumed_at` IS NULL
LIMIT 500;
```

建议以事务分批执行，直至影响行数为 0：

```sql
START TRANSACTION;
-- 重复执行上面的 DELETE
COMMIT;
```

### 2.2 已消费记录：保留 7 天后删除，删除前清空文本

```sql
-- 先清空文本（保留状态、音频摘要与时间用于排障）
UPDATE `interview_voice_transcription`
SET `text` = NULL, `updated_at` = UTC_TIMESTAMP(3)
WHERE `consumed_at` IS NOT NULL
  AND `consumed_at` < UTC_TIMESTAMP(3) - INTERVAL 7 DAY
  AND `text` IS NOT NULL
LIMIT 500;

-- 再删除超过 30 天的已消费记录
DELETE FROM `interview_voice_transcription`
WHERE `consumed_at` IS NOT NULL
  AND `consumed_at` < UTC_TIMESTAMP(3) - INTERVAL 30 DAY
LIMIT 500;
```

### 2.3 过期状态兜底（不依赖应用惰性过期）

```sql
UPDATE `interview_voice_transcription`
SET `status` = 'EXPIRED', `text` = NULL, `updated_at` = UTC_TIMESTAMP(3)
WHERE `expires_at` < UTC_TIMESTAMP(3)
  AND `status` IN ('PENDING','SUCCEEDED','EMPTY')
LIMIT 500;
```
