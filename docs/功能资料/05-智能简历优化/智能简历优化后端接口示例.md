## 接口状态

原始资料没有专属接口。以下为本次实现补充的最小契约，状态、错误、幂等和任务事件沿用公共约定。

### 关键假设

- 诊断和定向优化使用独立 Agent operation：`RESUME_DIAGNOSE`、`RESUME_OPTIMIZE`，均由 Java 创建任务并返回 `TaskVO`。
- 优化稿是与原简历版本、目标岗位关联的独立资源，不改写 `resume_version` 文件和已确认事实。AI 输出只是建议，用户逐段核对并采纳后才能导出。
- 原始文本仅用于本次授权任务；诊断项必须引用原文，优化建议不得新增雇主、项目、指标或技能事实。导出为 Java 同步生成文件，不创建 AI 任务。

### 创建简历诊断

`POST /api/v1/resume-optimizations/diagnoses`，请求 `{resumeVersionId}`，必须携带 `Idempotency-Key`，HTTP 202 返回 `TaskVO`，`resourceId=diagnosisId`。

### 查询诊断

- `GET /api/v1/resume-optimizations/diagnoses/{diagnosisId}`：返回 `{id,resumeVersionId,status,items,createdAt}`。
- `GET /api/v1/resume-optimizations/diagnoses?resumeVersionId=...&current=1&size=20`：分页查询本人历史，`items=[]`。

诊断状态为 `GENERATING/READY/FAILED`；诊断项为 `{id,priority,title,issue,quote,rationale,suggestion}`，`priority=IMPORTANT/SUGGESTION/NOTICE`，`quote` 必须能在原文中定位。

### 创建定向优化

`POST /api/v1/resume-optimizations`，请求 `{resumeVersionId,jobId,diagnosisId?}`，必须携带 `Idempotency-Key`，HTTP 202 返回 `TaskVO`，`resourceId=optimizationId`。简历必须为本人 `CONFIRMED` 版本，岗位必须可见且已分析。

### 查询优化稿

- `GET /api/v1/resume-optimizations/{optimizationId}`：返回 `{id,resumeVersionId,jobId,diagnosisId,status,title,sections,acceptedAt,createdAt}`。
- `GET /api/v1/resume-optimizations?resumeVersionId=...&jobId=...&current=1&size=20`：分页查询本人优化稿。

优化状态为 `GENERATING/READY/ACCEPTED/FAILED`。`sections[]` 为 `{sectionKey,title,originalText,suggestedText,sourceQuotes[]}`；原文与建议分开展示并标记“待本人核对”。

### 采纳优化稿

`POST /api/v1/resume-optimizations/{optimizationId}/accept`，请求 `{sections:[{sectionKey,title,content}]}`，必须携带 `Idempotency-Key`。完整替换全部段落并保存用户最终文本，状态进入 `ACCEPTED`；重复同内容请求返回原结果，内容变化需以当前 `acceptedAt` 作并发提示，不允许把未核对的 AI 文本隐式当成事实。

### 预览与导出

预览使用优化详情接口。`GET /api/v1/resume-optimizations/{optimizationId}/export?format=PDF|DOCX` 仅允许 `ACCEPTED`，由 Java 返回真实二进制文件及下载响应头，不允许跨用户访问。未采纳或生成失败返回 409，不伪造空文件。
