# 接口边界

前端只调用本文件的 `/api/v1`。所有AI业务先由Java创建任务；Java再调用[Agent内部接口](../接口设计/02-Agent模块接口文档.md)。Java回调接收接口仅Agent可访问。示例为演示，不是真实岗位、有效令牌或运行证据。

JSON使用camelCase；`?`表示值可为null，不等同参数可省略；是否允许省略由“是否必须”列决定。分页默认current=1、size=20，最大100；无记录返回total=0、records=[]。默认按createdAt DESC,id DESC稳定排序。所有资源ID须校验所有者，跨用户统一404，管理员接口同时检查角色。

## 邮箱注册

**接口地址**：`/api/v1/auth/register`

**请求方式**：`POST`

**请求数据类型**：`application/json`

**响应数据类型**：`application/json`

**接口描述**：创建账户及空画像。邮箱仅作登录标识；P0不发送邮件。

**权限**：公开。

**请求示例**：

```json
{
  "email": "demo@example.com",
  "password": "ExampleOnly_123",
  "nickname": "张同学"
}
```

**请求参数**：

| 参数名称 | 参数说明 | 请求类型 | 是否必须 | 数据类型 | schema |
| --- | --- | --- | --- | --- | --- |
| email | 合法邮箱≤254 | body | true | string |  |
| password | 10..72字符，不记录日志 | body | true | string |  |
| nickname | 1..30字符 | body | true | string |  |

**响应状态**：

| 状态码 | 说明 | schema |
| --- | --- | --- |
| 200 | 操作成功 | CommonResult&lt;UserVO&gt; |
| 400 / 401 / 403 / 404 / 409 / 429 / 500 | 详见公共错误码 | CommonError |

**响应参数**：

| 参数名称 | 参数说明 | 类型 | schema |
| --- | --- | --- | --- |
| code | 业务码，200成功/202受理 | integer |  |
| msg | 提示信息 | string |  |
| data | 业务数据 | UserVO | UserVO |
| traceId | 关联排障ID | string |  |
| &emsp;id | 用户ID | uuid |  |
| &emsp;email | 邮箱 | string |  |
| &emsp;nickname | 昵称 | string |  |
| &emsp;role | USER/ADMIN | string |  |
| &emsp;createdAt | UTC时间 | datetime |  |

**响应示例**：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "id": "10000000-0000-4000-8000-000000000001",
    "email": "demo@example.com",
    "nickname": "张同学",
    "role": "USER",
    "createdAt": "2026-10-27T02:00:00Z"
  },
  "traceId": "demo-trace-20261027"
```

## 密码登录

**接口地址**：`/api/v1/auth/login`

**请求方式**：`POST`

**请求数据类型**：`application/json`

**响应数据类型**：`application/json`

**接口描述**：返回短期访问令牌，并设置刷新Cookie。账号或密码错误使用同一提示。

**权限**：公开。

**请求示例**：

```json
{
  "email": "demo@example.com",
  "password": "ExampleOnly_123"
}
```

**请求参数**：

| 参数名称 | 参数说明 | 请求类型 | 是否必须 | 数据类型 | schema |
| --- | --- | --- | --- | --- | --- |
| email | 登录邮箱 | body | true | string |  |
| password | 密码 | body | true | string |  |

**响应状态**：

| 状态码 | 说明 | schema |
| --- | --- | --- |
| 200 | 操作成功 | CommonResult&lt;TokenVO&gt; |
| 400 / 401 / 403 / 404 / 409 / 429 / 500 | 详见公共错误码 | CommonError |

**响应参数**：

| 参数名称 | 参数说明 | 类型 | schema |
| --- | --- | --- | --- |
| code | 业务码，200成功/202受理 | integer |  |
| msg | 提示信息 | string |  |
| data | 业务数据 | TokenVO | TokenVO |
| traceId | 关联排障ID | string |  |
| &emsp;accessToken | 用户Bearer令牌 | string |  |
| &emsp;expiresIn | 有效秒数 | integer |  |
| &emsp;user | 用户 | UserVO | UserVO |

**响应示例**：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "accessToken": "example-access-token",
    "expiresIn": 900,
    "user": {
      "id": "10000000-0000-4000-8000-000000000001",
      "email": "demo@example.com",
      "nickname": "张同学",
      "role": "USER",
      "createdAt": "2026-10-27T02:00:00Z"

  "traceId": "demo-trace-20261027"
```

**业务规则**：默认accessToken 15分钟，refreshToken 7天；Secure/HttpOnly/SameSite=Lax；账号和IP双重限流。

## 领取CSRF令牌

**接口地址**：`/api/v1/auth/csrf`

**请求方式**：`GET`

**请求数据类型**：`无请求体`

**响应数据类型**：`application/json`

**接口描述**：页面刷新后恢复与当前Cookie会话绑定的CSRF值；同源检查，仅向受信任Origin返回，不刷新accessToken。

**权限**：公开。

**请求示例**：

```http
GET /api/v1/auth/csrf HTTP/1.1

```

**请求参数**：

| 参数名称 | 参数说明 | 请求类型 | 是否必须 | 数据类型 | schema |
| --- | --- | --- | --- | --- | --- |
| refreshToken | 当前刷新会话Cookie，浏览器发送 | cookie | true | string |  |

**响应状态**：

| 状态码 | 说明 | schema |
| --- | --- | --- |
| 200 | 操作成功 | CommonResult&lt;object&gt; |
| 400 / 401 / 403 / 404 / 409 / 429 / 500 | 详见公共错误码 | CommonError |

**响应参数**：

| 参数名称 | 参数说明 | 类型 | schema |
| --- | --- | --- | --- |
| code | 业务码，200成功/202受理 | integer |  |
| msg | 提示信息 | string |  |
| data | 业务数据 | object | object |
| traceId | 关联排障ID | string |  |

**响应示例**：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "csrfToken": "example-csrf-token"
  },
  "traceId": "demo-trace-20261027"
}
```

**业务规则**：无有效Cookie会话401。可重新轮换csrf_hash；前端使用响应data.csrfToken请求/auth/refresh。登录/刷新也通过X-CSRF-Token响应头提供新值，跨域时显式Expose-Headers。

| --- | --- | --- | --- | --- | --- |
| Authorization | Bearer 内部服务JWT | header | true | string |  |

| result | 成功必填，类型由operation判别，失败为null | body | true | object? |  |

| 状态码 | 说明 | schema |
| --- | --- | --- |

| 参数名称 | 参数说明 | 类型 | schema |

```json
  "msg": "操作成功",

    "accepted": true,

  },
```

**业务规则**：校验aud=career-business、scope=ai:callback及taskId范围。回调主体≤2MiB。重复相同结果200 accepted=true；同一runId不同结果409；任务已取消/过期返回200 accepted=false，不产生副作用。Java业务提交失败返回503，Agent按退避重试；校验失败422且Java记录失败。分发应答丢失时先从Agent按taskId查run再绑定，不接受任意runId。

## 刷新本任务简历文件授权

**接口地址**：`/internal/business/v1/ai-tasks/{taskId}/file-access`

**请求方式**：`POST`

**请求数据类型**：`application/json`

**响应数据类型**：`application/json`

**接口描述**：仅RESUME_PARSE任务允许，为该任务绑定的私有简历版本重新签发5分钟文件URL。

**权限**：内部。

**请求示例**：

```json
{}
```

**请求参数**：

| 参数名称 | 参数说明 | 请求类型 | 是否必须 | 数据类型 | schema |
| --- | --- | --- | --- | --- | --- |

**响应状态**：

**响应参数**：

| 参数名称 | 参数说明 | 类型 | schema |
| --- | --- | --- | --- |
