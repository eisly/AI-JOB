## 一轮搜索如何执行

| 环节 | 当前执行逻辑 |
| --- | --- |
| 前端与任务入口 | 岗位搜索页提交 `POST /api/v1/job-searches`。Java 校验画像版本、生效简历与求职偏好，固化画像、搜索条件、来源与限制，创建 `JOB_SEARCH` 异步任务。Agent 执行 LangGraph，Java 接收结果回调，落库后前端按 rank 分页展示。前端分页仅查询已入库结果。 |
| 关键词与查询 | 优先使用显式关键词，空缺时由画像的目标岗位映射。规则扩展最多 8 个词，按招聘类型分组、城市轮转，拼入招聘类型和「招聘 职位」；首轮计划默认至多 12 条（城市数更多时计划可增，执行上限仍受预算）。启用 Web Provider 时另向模型请求一个等价词，限 10 秒，超时走规则；模型等价词可成为补搜上下文关键词，实际 Provider 请求仍由 query specs 驱动。补搜为覆盖缺口生成新 query。基线初始计划 6 条，默认组合另生成 7 条，Web 对照另生成 21 条。 |
| 来源调度 | 首轮并发执行所有已选非 Web 来源，等它们返回后再决定是否运行 Web。若未关闭的官网候选数少于 `maxResults`，城市或招聘类型有缺口，或者任一官网候选缺薪资或规模，则运行 Web。前 3 个官网候选中符合缺字段条件的，优先拼公司、岗位、城市的补字段查询。有第三方候选和剩余预算时，最多以 3 个候选反查官网。后续补搜只运行 Web。 |
| Tavily 与 Provider | 当前本地 Agent 配置可加载 Tavily，Brave 未启用。配置 Brave 后，同一条 query 会分别调用两个 Provider。Tavily 请求使用 `general`、中国、`zh-cn`、`basic`、Markdown 正文和 `max_results`，Web 常见每条 query 取 10 条；默认 12 秒请求超时、最多额外重试 1 次。默认 30 天新鲜度没有向 Tavily 传 `time_range`，初始计划仅在新鲜度不超过 7 天时传周范围。Tavily 没有翻页循环，Brave 未传 `offset`。 |
| 官网及 ATS 分页 | `company_official` 复用 Web Provider，在最多 4 个查询后加「公司官网 招聘」，每轮最多选 6 页，再验证企业归属。百度最多 4 个岗位词和招聘类型组合，每个只取首屏。腾讯只请求 `pageIndex=1`，在本地筛城市与类型。Greenhouse 拉已配置 board 的职位列表后过滤，当前只有 Stripe；配置多 board 时最多查 3 个，够当前来源限额可提前退出。Lever 当前无 board、也未列入默认来源。猎聘、BOSS 直聘和智联没有启用独立直连适配器，公开页面可经 Web 进入。 |
| 预算与页面调度 | 默认每轮共享 12 查询、20 个页面名额，最多 3 轮。正文预抓 12 次、详情核验 20 次、内部 API 计数 60 为全任务预算。总预算配置 150 秒，采集实际留 120 秒，后 30 秒预留给后处理。企业官网等非 Web 来源外层通常 15 秒，Web 单轮外层最多 90 秒。正文抓取和 Provider 重试等与内部计数口径不同，`apiCalls` 无法代表实际外发请求或账单。旧 `web_query_limit` 仍被计算并传递，Web 实际按共享 `queries_remaining()` 选 query。 |
| 页面预抓与核验 | 先规范化搜索结果 URL，去掉无有效 URL、标题或正文的命中，合并同 URL，再按域名轮转。普通 Web 单轮至多选 10 页，剩余存入来源自己的待处理队列。选中的页面在额度内预抓正文和结构化字段，失败时仍可使用 Provider 返回内容；共用详情缓存，薄页可尝试渲染。提取后才执行岗位详情核验和字段补全。核验区分确认、可能、未知和关闭，403、404、超时或证据不足可记为未知，明确下线或截止才记关闭。 |
| 从网页提取岗位 | 5 页一批，默认 20 秒模型外层超时，页正文最多 6,500 字符。按 `pageIndex` 对齐，每页至多接受 1 条。标题与页面不符、JD 引文无法回到正文、JD 少于 35 字符等会拒绝。随后按已知不符的城市、招聘类型和规模筛除；未知城市和类型可保留并标记，未知规模受开关影响。非 Web 来源以及特定 Web 关键词（`Java 后端`、`AI 应用开发`）另有相关性过滤。百度、腾讯和 ATS 主要从列表字段构造岗位，详情核验为 0 不代表这些来源没有在招证据。 |
| Python 去重和 JD 理解 | 丢弃缺标题、公司、JD 或 HTTPS 链接的岗位。按规范 URL、岗位 ID、兼容指纹、同城跨域 JD 相似度合并，优先官网并保留来源和字段证据。Python 去重后先按上限截断，再解析 JD，每批 8 条、每条最多 3,000 字符、每批最多 15 秒。JD 理解提取学历、经验、届次和技能等要求，检查原文证据，返回语义分。超时或岗位行缺失时规则降级并保留候选。Python 排序权重为相关性 25%、新鲜度 20%、完整度 15%、在招核验 20%、语义 10%、来源 10%。 |
| Java 资格与最终排序 | 回调再校验必填字段、HTTPS、城市、招聘类型、规模，并按精确 URL 再去重。资格比较画像的学历、毕业年份、经验与 JD 要求，输出 `PASS`、`UNKNOWN`、`FAIL`。搜索列表中 `FAIL` 的匹配分为空，仍可进入排序；下游工作台匹配查询另有排除 `FAIL` 的条件。匹配分按技能 60%、语义 25%、偏好 15%，缺项按有效权重重算。最终先按资格分组（关闭放最后），再按匹配分、在招核验、字段完整度、来源、发布时间和指纹排序，最后按请求上限截断并持久化。 |

代码入口与实现见 [前端 API](../../project/frontend/src/api/job-searches.ts)、[Java 搜索服务](../../project/backend/src/main/java/com/aijob/backend/job/JobSearchService.java)、[Agent 搜索编排](../../project/agent/app/search/pipeline.py)、[Web 来源](../../project/agent/app/search/sources/web.py)、[Tavily Provider](../../project/agent/app/search/providers/tavily.py)、[去重与排序](../../project/agent/app/search/dedupe.py)、[Java 回调处理器](../../project/backend/src/main/java/com/aijob/backend/job/JobSearchResultHandler.java) 与 [列表查询](../../project/backend/src/main/java/com/aijob/backend/job/JobSearchMapper.java)。

## 提前停止与指标问题

1. **待处理链接没有驱动续跑。** Web 在 `source_extras['web']['pending_pages']` 留下队列，路由和最终待处理告警读的是 `web_budget['pending']`，两者没有同步。离线探针用一个剩余页面和三次成功查询验证，`found=30 / analyzed=0 / extracted=0 / completed=true` 时路由直接进入 `normalize`。覆盖格按城市×岗位类别统计，默认三次查询尝试就可完成，企业官网和 Web 共用覆盖矩阵。实跑默认组合 4/4 格标为完成，全部 `analyzed=0`、`extracted=0`。
2. **续跑阈值早于用户上限。** 只有 Web 状态可继续且存在覆盖缺口或可见队列时才检查续跑。达到 3 轮、时间或 API 预算耗尽都会停止；有效候选达到 10 且本轮 Web 无新增时，即使仍有缺口也停；无覆盖缺口时达到 5 或本轮无新增也会停。这里的候选数是原始有效岗位的不同指纹数，在全局去重和 Java 资格之前计算。补搜还会把已计划但未必已发出的 query 从下一次生成的候选词中排除。
3. **来源竞争存在，效果待对照。** 默认 15 秒的企业官网来源使用与 Web 相同的模型提取，而单批提取本身最多 20 秒，前面还要请求 Provider 和抓正文。首轮等待官网可减少 Web 的剩余时间与正文预抓名额。官网跳过 Web 的判断发生在全局去重及 Java 资格校验前，满足条数与字段条件时，Web 可能无独立状态行。当前快照已经执行 Web，且 Web 单独运行仍为 0。当前本地 DeepSeek 使用 `deepseek-v4-pro`、thinking 开启、effort 为 `high`，关键词／网页提取／JD 理解外层分别约 10／20／15 秒。
4. **总览漏斗会高估命中和模型成功率。** 跨轮 `sourceStatus` 合并后，累计命中被再次写入全局漏斗，默认组合报 239 对来源明细 159，Web 对照报 420 对 180。`extractionSuccess=8` 统计 JD 理解阶段返回的候选数，包含 8 条规则降级；`pagesExtracted` 是送入提取的页次，包含批次失败。`metrics.failures={}` 也不会反映整批模型失败。Java summary 的 `uniqueCount` 是截断后的条数，`droppedCount` 合并了无效字段与多种硬条件，Agent 的完整 `metrics` 未写入该 summary。

对应实现见 [续跑与汇总](../../project/agent/app/search/pipeline.py)、[覆盖矩阵](../../project/agent/app/search/expansion.py)、[预算判断](../../project/agent/app/search/budget.py) 与 [Java 结果摘要](../../project/backend/src/main/java/com/aijob/backend/job/JobSearchResultHandler.java)。

## 后续验收顺序

1. 优先验证网页提取的时限与模型配置。用同一批固定公开页面回放，分别记录超时、空输出、有效行和逐条证据拒绝数，单独检查公司归属。已有证据表明，仅增加 Tavily 请求量会把更多链接交给当前无法稳定完成的提取阶段。
2. 验证实际待处理队列、覆盖状态和停止原因。固定 Provider 返回做有无官网优先的回放，记录各来源开始／结束时间、独立与共享预算、待处理唯一 URL、正文成功数，以及每个来源停在哪个条件。再确定是否需要改变首屏限制、官网预算或 Provider 覆盖。
3. 用完整 Agent payload 跑隔离的 Java 回调样本，按原因分开统计字段无效、城市／招聘类型／规模不匹配、重复、资格三态和 Top N 截断。已有边界探针记录画像学历 `null` 对本科要求为 `UNKNOWN`、字面值 `UNKNOWN` 为 `FAIL`，技能-only 要求为 `PASS`；这两项边界需要资格分布验证。

本次使用现有真实调用快照、当前工作区源码、当前 Agent 配置和离线探针，另有 30 项 Python 定向用例、20 项 Java 定向用例通过。实测范围止于现有外网快照和本地隔离验证。正文成功率、腾讯原始结果数、Stripe 淘汰原因分布和目标岗位真实召回率缺少可用分母或标注。
