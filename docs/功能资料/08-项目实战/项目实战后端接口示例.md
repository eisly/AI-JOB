## 接口状态

原始资料没有专属接口。以下为本次实现补充的最小契约，状态、错误、幂等和任务事件沿用公共约定。

### 关键假设

- 项目推荐和计划生成使用独立 Agent operation：`PROJECT_RECOMMEND`、`PROJECT_PLAN`。推荐是 AI 建议而非用户既有经历；计划任务进度与交付记录由 Java 管理。
- 推荐可关联本人有效匹配条目，也可只使用当前确认画像和技能目录；不提供匹配条目时不虚构岗位信息。
- 项目推荐会先由 Agent 通过 GitHub 公共 API 检索真实仓库候选，再由模型从候选白名单中选择；模型不得自行编造仓库地址或元数据。GitHub 不可用、限流或没有可用候选时，继续生成 `AI_GENERATED` 练习项目，并在来源字段中明确标记。
- 多个目标技能按“单个仓库尽可能覆盖更多技能”推荐：先检索技能交集，不足时扩大候选池，再按仓库匹配技能数量降序、Star 数降序排序，不为每个技能单独分配项目。`skillCodes` 包含该仓库实际匹配的全部目标技能，与 `repository.matchedSkillCodes` 对应；匹配依据为仓库主题、主语言、名称和描述，不代表已运行验证代码。没有全技能交集时返回实际覆盖最多的候选，AI 降级方案则尽可能整合已选技能。
- 推荐集合优先保留综合覆盖最多的项目，再选择能补齐未覆盖技能的候选；不只保留最高覆盖数并列项。仓库充足时提供 3..6 个不同项目，不足时返回实际数量；整个推荐集合的技能并集须包含全部目标技能，GitHub 无法覆盖的技能通过明确标记的 AI 练习方案补充，仍最多六项。
- 用户选定一个候选后生成独立实战计划，仅练习该候选列出的技能；整组候选技能覆盖全部目标不等于选中任意一个项目就能练习全部技能。项目任务勾选和交付记录持久化，项目总进度按已完成任务数计算，不由 AI 评分。

### 创建项目推荐

`POST /api/v1/projects/recommendations`，请求 `{matchItemId?,skillCodes?,difficulty?,maxDurationWeeks?}`，必须携带 `Idempotency-Key`，HTTP 202 返回 `TaskVO`，`resourceId=recommendationId`。技能最多 5 个，难度为 `BEGINNER/INTERMEDIATE/ADVANCED`，周期 1..12 周。

### 查询推荐

`GET /api/v1/projects/recommendations/{recommendationId}` 返回 `{id,status,items,createdAt,targetSkillCodes,coveredSkillCodes,githubCoveredSkillCodes,missingSkillCodes}`，状态为 `GENERATING/READY/FAILED`。候选项为 `{id,title,summary,skillCodes,missingSkillCodes,difficulty,estimatedWeeks,reason,deliverables[],sourceType,source,repository}`；所有技能必须属于 Java 提供的技能目录。

- `targetSkillCodes` 为生成时冻结的目标技能，不随界面当前表单改变；`coveredSkillCodes` 为全部候选的技能并集与目标技能的交集，`githubCoveredSkillCodes` 只统计真实仓库匹配，根 `missingSkillCodes` 为整组仍未覆盖的目标技能。每项 `missingSkillCodes` 为本项目缺少的目标技能。
- 新推荐将目标技能和候选快照保存在现有 `project_recommendation.items_json` 对象 `{targetSkillCodes,items}` 中，不新增数据库列；历史数组快照仍可读取，因缺少冻结目标不推测或显示覆盖率，需要重新生成才能获得覆盖信息。

- `sourceType=GITHUB_REPOSITORY`：真实仓库项目，`source=GITHUB_API`，`repository` 包含 `fullName`、`htmlUrl`、`description`、`stargazersCount`、`language`、`pushedAt`、`topics`、`matchedSkillCodes`、`verifiedAt`。
- `sourceType=AI_GENERATED`：练习项目方案；`source` 为 `MODEL` 或 `LOCAL_RULES`，`repository` 为 `null`，不代表现实中已经存在同名项目。

### 生成实战计划

`POST /api/v1/projects/plans`，请求 `{recommendationItemId,weeklyHours}`，`weeklyHours=1..40`，必须携带 `Idempotency-Key`，HTTP 202 返回 `TaskVO`，`resourceId=projectId`。

### 查询项目与计划

- `GET /api/v1/projects`：分页返回本人项目。
- `GET /api/v1/projects/{projectId}`：返回 `{id,title,summary,status,progress,weeklyHours,skillCodes,milestones,deliverables,version,createdAt}`。

项目状态为 `GENERATING/ACTIVE/COMPLETED/FAILED`；里程碑为 `{id,seq,title,description,tasks[]}`，任务为 `{id,title,description,estimatedHours,status}`，任务状态为 `PENDING/IN_PROGRESS/COMPLETED`。`progress` 为已完成任务数/全部任务数的整数百分比，无任务时为 0。

### 更新任务进度

`PATCH /api/v1/projects/{projectId}/tasks/{taskId}`，请求 `{status,expectedVersion}`。Java 校验归属和版本后保存任务状态、重算项目进度；全部任务完成时项目为 `COMPLETED`，否则为 `ACTIVE`，返回完整项目详情。

### 保存交付记录

`POST /api/v1/projects/{projectId}/deliverables`，请求 `{taskId,title,url?,notes?}`，必须携带 `Idempotency-Key`。`url` 只允许 http/https；交付记录追加保存并随项目详情返回，不把链接或 AI 内容自动视为代码已验收。
