# 项目实战后端接口

2026-11-16 设计更新。新版「发现项目」搜索 GitHub、Gitee、GitCode 的公开仓库，用户选中项目后可查看仓库、README 和建议学习步骤，再生成实战计划。多平台发现和仓库来源字段均为待实现契约。

关联资料：[UI 与交互说明](项目实战UI与交互说明.md) · [统一接口约定](../业务后端接口文档.md) · [任务中心接口](../12-任务中心/任务中心后端接口示例.md)。

## 接口一览

| 方法和路径 | 用途 | 状态 |
| --- | --- | --- |
| `POST /api/v1/projects/recommendations` | 创建推荐任务 | 已有任务入口，拟扩展搜索条件并改用仓库检索 |
| `GET /api/v1/projects/recommendations/{recommendationId}` | 查询搜索结果与项目详情 | 已有批次查询，拟扩展来源、检索状态与学习步骤 |
| `POST /api/v1/projects/plans` | 为选中的项目生成计划 | 已有接口，拟将选中仓库的来源写入计划快照 |
| `GET /api/v1/projects` | 分页查询「我的实战」 | 已有接口 |
| `GET /api/v1/projects/{projectId}` | 查询计划、进度和交付 | 已有接口，拟扩展计划来源 |
| `PATCH /api/v1/projects/{projectId}/tasks/{taskId}` | 更新任务状态 | 已有接口 |
| `POST /api/v1/projects/{projectId}/deliverables` | 添加交付记录 | 已有接口 |

接口需要登录并校验资源归属，使用 `CommonResult<T>`。本文 JSON 示例展示请求体或响应的 `data`。创建推荐、生成计划和保存交付需传 `Idempotency-Key`。两个异步创建接口均返回 HTTP 202 和 `TaskVO`。前端用任务 ID 订阅任务事件或查询任务，用 `resourceId` 读取对应业务详情。

## 1. 创建项目推荐

`POST /api/v1/projects/recommendations`，任务为 `PROJECT_RECOMMEND`，`resourceId` 为推荐批次 ID。

```json
{
  "query": "Spring Boot",
  "sources": ["GITHUB", "GITEE", "GITCODE"],
  "skillCodes": ["JAVA"]
}
```

| 请求字段 | 约定 |
| --- | --- |
| `query` | 新增，可选。仓库名、技术栈或项目关键词。去除首尾空白，留空时按当前求职画像、所选技能或有效岗位匹配推荐 |
| `sources` | 新增，可选。枚举为 `GITHUB`、`GITEE`、`GITCODE`。省略表示全部平台，传入时至少一个有效枚举，并去重 |
| `difficulty` | 可选，沿用 `BEGINNER`、`INTERMEDIATE`、`ADVANCED`。新版省略表示不限。上线需同步调整 Java 和 Agent 的历史默认 `INTERMEDIATE` 及候选难度校验 |
| `skillCodes` | 可选，最多 5 个，来自技能目录。可由求职画像或用户已选技能带入 |
| `matchItemId` | 可选，仅接收本人有效的岗位匹配条目，沿用归属、状态及版本校验 |
| `maxDurationWeeks` | 可选，1–12 周，省略时为 12 周。用于控制建议的学习周期 |

同一点击重发时复用原幂等键。用户更改关键词或筛选后发起新搜索，使用新的幂等键。

## 2. 查询推荐与项目详情

`GET /api/v1/projects/recommendations/{recommendationId}`。以下为新版的成功示例，左侧结果和右侧详情使用同一条候选记录。

```json
{
  "id": "10000000-0000-4000-8000-000000000001",
  "mode": "REPOSITORY",
  "status": "READY",
  "createdAt": "2026-11-16T05:30:00Z",
  "sourceRuns": [
    {"platform": "GITHUB", "status": "SUCCEEDED"},
    {"platform": "GITEE", "status": "SUCCEEDED"},
    {"platform": "GITCODE", "status": "SUCCEEDED"}
  ],
  "items": [
    {
      "id": "20000000-0000-4000-8000-000000000001",
      "title": "Sa-Token",
      "summary": "轻量级 Java 权限认证框架，提供登录、会话管理和权限校验。",
      "skillCodes": ["JAVA"],
      "difficulty": "INTERMEDIATE",
      "estimatedWeeks": 2,
      "reason": "适合熟悉 Spring Boot 基础、想练习登录和接口鉴权的候选人。",
      "gettingStarted": [
        "查看 README，找到 Spring Boot 示例",
        "启动示例，体验登录与退出",
        "为一个接口添加权限校验并编写测试"
      ],
      "deliverables": ["Spring Boot 示例的运行说明", "接口权限校验及测试"],
      "primarySource": {
        "platform": "GITEE",
        "path": "dromara/sa-token",
        "url": "https://gitee.com/dromara/sa-token",
        "readmeUrl": "https://gitee.com/dromara/sa-token/blob/dev/README.md"
      },
      "alternateSources": [
        {
          "platform": "GITCODE",
          "path": "dromara/sa-token",
          "url": "https://gitcode.com/dromara/sa-token",
          "readmeUrl": null
        }
      ]
    }
  ]
}
```

| 字段 | 约定 |
| --- | --- |
| `mode` | `REPOSITORY` 为新版仓库结果，`LEGACY_IDEA` 为历史 AI 或规则练习建议 |
| `status` | `GENERATING`、`READY`、`FAILED`。批次状态与任务状态通过同一任务流程更新 |
| `sourceRuns` | 新增。仅记录本次选中平台，状态为 `SUCCEEDED` 或 `FAILED`。处理中可为空，失败诊断优先使用任务中心的错误信息 |
| `items[]` | 新版可返回 0–6 条，先去重再按相关度排序取候选。候选 `id` 为生成计划使用的 ID |
| `title`、`summary` | 仓库名称与项目概述。概述从仓库描述或 README 提炼。两者均缺少足够信息时跳过该仓库 |
| `skillCodes`、`difficulty`、`estimatedWeeks` | 技能标签、学习难度和建议周期。技能编码受服务端允许目录约束，建议周期为 1 至 `maxDurationWeeks` 周 |
| `reason`、`gettingStarted[]`、`deliverables[]` | 推荐理由、入门步骤和预期交付。基于候选人画像和仓库资料给出学习建议 |
| `primarySource` | 新版候选必填。包含来源平台、仓库路径、直达仓库的 URL 和可空的 README URL |
| `alternateSources[]` | 新增。经核对属于同项目的其他仓库入口。没有其他来源时返回空数组 |

### 来源校验与排序

- 检索层从公开仓库获取标题、描述、链接和 README 入口。服务端确认链接与来源平台对应且指向公开仓库，仅返回 HTTPS 链接。README 无法确认时返回 `null`。学习建议应以这批候选为输入，仓库地址由检索层提供。
- 同平台按规范化仓库地址去重。跨平台仅在项目文档互链或其他可信证据能确认同源时合并，保留本次选中平台上的可访问主入口。优先选择资料更完整的来源，其他确认过的地址放到 `alternateSources`。查询只选 Gitee 时，主入口为 Gitee。
- 推荐排序考虑关键词、求职方向和技能相关度，以及 README 对入门的帮助。难度选「不限」时允许不同难度共同出现。

### 结果与兼容

| 情形 | 返回与页面处理 |
| --- | --- |
| 所选平台均成功且有结果 | `READY`，展示候选 |
| 所选平台均成功但无结果 | `READY` 和 `items: []`，提示调整关键词或筛选 |
| 部分平台失败 | `READY`，保留成功平台结果，通过 `sourceRuns` 显示缺失的平台。即使结果为空，也显示来源失败以及重试入口 |
| 所选平台全部失败或检索任务失败 | `FAILED`，使用任务错误信息显示重试提示 |
| 查询旧批次 | `LEGACY_IDEA`，保留既有字段，`primarySource` 为 `null`，新增列表字段为空。旧计划仍可在「我的实战」访问 |

只要仓库检索有合格候选，模型失败时可据仓库资料给出简短的规则化学习提示。搜索空结果和失败状态按上表返回。上线时须同步调整现有 Agent、Java 的候选数量校验和缺省难度处理。

## 3. 生成实战计划

`POST /api/v1/projects/plans`，任务为 `PROJECT_PLAN`，`resourceId` 为项目 ID。

```json
{
  "recommendationItemId": "20000000-0000-4000-8000-000000000001",
  "weeklyHours": 4
}
```

- `recommendationItemId` 必须属于当前用户且所在批次为 `READY`。`weeklyHours` 为 1–40 的整数。
- 新版服务端从所选候选读取项目概述、学习步骤和 `primarySource`，在创建计划时记录来源快照，传入计划任务。后续搜索产生的新批次不会改变已保存计划的仓库链接。
- 计划输出包含标题、概述、里程碑和任务。总工时不超过 `weeklyHours × estimatedWeeks`。已有历史推荐项继续使用原计划流程，其来源快照为 `null`。

## 4. 查询计划、更新进度和保存交付

| 接口 | 参数与结果 |
| --- | --- |
| `GET /api/v1/projects?current=1&size=20` | 分页返回本人项目摘要，包含 `total`、`records`、`current`、`size` |
| `GET /api/v1/projects/{projectId}` | 返回 `ProjectVO`，包括 `id`、`recommendationItemId`、`taskId`、`title`、`summary`、`status`、`progress`、`weeklyHours`、`skillCodes`、`milestones`、`deliverables`、`version`、`createdAt`、`updatedAt`。新版拟增加 `primarySource`，沿用候选中相同结构，旧计划为 `null` |
| `PATCH /api/v1/projects/{projectId}/tasks/{taskId}` | 请求 `{status, expectedVersion}`。校验归属、状态和版本，更新任务并重算项目进度，返回完整计划。版本冲突时前端重新加载 |
| `POST /api/v1/projects/{projectId}/deliverables` | 请求 `{taskId, title, url?, notes?}`，`url` 允许 HTTP/HTTPS。追加交付并返回完整计划 |

计划状态为 `GENERATING/ACTIVE/COMPLETED/FAILED`。里程碑为 `{id, seq, title, description, tasks[]}`，任务为 `{id, title, description, estimatedHours, status}`。任务状态为 `PENDING/IN_PROGRESS/COMPLETED`。Java 按已完成任务数除以任务总数计算整数百分比，无任务时为 0，全部任务完成时计划为 `COMPLETED`。交付记录是用户提交的链接或备注，任务完成状态通过任务更新接口维护。
