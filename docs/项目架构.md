我建议采用 Java Spring Boot＋Python FastAPI＋Agent 的双后端架构。

而且对于我们的 AI 一站式智能求职平台，这个技术方案比纯 Java 或纯 Python 更合适。

原因不只是为了技术栈丰富，而是因为我们的项目本来就包含两类不同的业务：

- 传统互联网业务：用户管理、简历管理、岗位数据管理、收藏投递、学习记录、面试记录等。
- AI 智能业务：简历解析、岗位语义匹配、能力差距分析、动态八股文训练、多轮模拟面试、多 Agent 协作等。

我们可以让 Java 和 Python 各自负责擅长的部分。

## 一、总体技术架构

前端：Vue 3＋TypeScript

求职工作台 · 岗位推荐 · 刷题 · 模拟面试 · 成长报告

Java 业务后端：Spring Boot

身份认证 · 用户管理 · 岗位管理 · 简历存储 · 学习记录 · 业务 API

HTTP REST / SSE / 内部服务鉴权

Python AI 服务：FastAPI＋Agent

模型调用 · RAG · JD 理解 · 智能面试 · 训练规划 · 工具调用

MySQL

业务数据与能力证据

Redis

缓存、会话及任务状态

Qdrant

知识库向量检索

底层 AI 能力

千问 API / Embedding / Rerank / ASR / TTS

上图是逻辑架构，实际数据库访问应按服务职责划分，不建议两个服务随意修改同一批业务表。

核心原则：Java 管理业务状态和数据，Python 负责 AI 推理与工作流，前端统一通过 Java 后端访问系统。

## 二、技术栈最终选型

| 模块        | 推荐技术                  | 说明                       |
| ----------- | ------------------------- | -------------------------- |
| 前端        | Vue 3 + TypeScript + Vite | 前后端分离                 |
| UI 组件     | Element Plus              | 后台工作台和表单           |
| Java 版本   | JDK 21                    | LTS 版本                   |
| Java 后端   | Spring Boot 4.x           | 核心业务服务               |
| 安全认证    | Spring Security + JWT     | 登录与接口权限             |
| ORM         | MyBatis                   | 数据库访问                 |
| Python 后端 | Python 3.11+ + FastAPI    | AI 服务接口                |
| Agent 框架  | LangGraph                 | 多步骤 Agent 工作流        |
| 大语言模型  | 阿里云百炼 / 千问 API     | AI 推理和结构化输出        |
| 数据库      | MySQL 8                   | 持久化业务数据             |
| 缓存        | Redis                     | 缓存、会话及临时状态       |
| 向量数据库  | Qdrant                    | JD / 技术知识语义检索      |
| 实时输出    | SSE                       | 文字面试和生成过程流式展示 |
| 部署        | Docker Compose + Nginx    | 容器化部署                 |

Spring Boot 4 已经可以正常作为项目基础，官方要求 Java 17 及以上，采用 JDK 21 是合理选择。

这里有三个暂不强制引入的组件： RabbitMQ、Elasticsearch 和 Kubernetes。第一版的业务量不值得为了技术栈完整而增加维护成本。

## 三、七大功能分别由谁负责？

| 功能           | Spring Boot                  | Python Agent                 |
| -------------- | ---------------------------- | ---------------------------- |
| 求职画像       | 用户信息、求职偏好、档案存储 | 简历解析、技能提取           |
| 智能简历优化   | 文件管理、版本管理           | 简历诊断、JD 定向优化        |
| 精准岗位推荐   | 岗位库、资格规则、收藏投递   | JD 理解、语义匹配、推荐解释  |
| 动态八股文训练 | 题库、答题记录、错题管理     | 学习规划、答案评价、动态出题 |
| 项目实战推荐   | GitHub 项目记录、任务进度    | 项目分析、学习任务生成       |
| 模拟面试       | 面试记录、会话管理           | 问题生成、多轮追问、答案评估 |
| 成长中心       | 进度统计、能力证据存储       | 能力差距分析、下一步学习建议 |

我特别建议：规则明确的任务交给 Java，语义理解和不确定性推理交给 Python。

例如学历、毕业年份、工作年限等岗位资格判断，不应该全部交给 LLM 自由判断。Java 可以执行确定性规则，而 Python 负责把复杂 JD 转换成可校验的结构化字段。

## 四、Java 和 Python 怎么通信？

以用户进行模拟面试为例。

Vue 3 前端

用户开始一次 Java 后端面试

Spring Boot

认证用户、建立面试会话、读取简历和岗位 JD

FastAPI + Interview Agent

生成问题、理解回答、动态追问

Spring Boot

转发 SSE 流、存储面试结果、更新能力证据

Vue 3 前端

展示面试对话、评分报告和改进建议

Java 调用 Python 推荐使用 Spring `WebClient`，通过内部 REST API 交互。

接口可以先规划成：

```
Java 对外接口：
POST /api/resumes/upload
POST /api/jobs/match
POST /api/learning/plan
POST /api/interviews
POST /api/interviews/{id}/answers
GET  /api/interviews/{id}/report

Python 内部接口：
POST /internal/resume/parse
POST /internal/job/analyze
POST /internal/learning/generate
POST /internal/interview/next
POST /internal/interview/evaluate
```

文字面试推荐使用 SSE；FastAPI 官方已经支持标准的 SSE 响应以及 POST 请求流式输出。

## 五、Agent 框架要不要一开始就上 LangGraph？

可以选择 LangGraph，但不要一上来就同时实现五个复杂 Agent。

它支持持久化工作流状态和暂停恢复等机制，适合后续做多步骤任务与多轮面试。

第一阶段可以这样实现：

- Profile Agent：简历提取与标准化。
- Job Agent：JD 结构化分析与推荐理由。
- Learning Agent：学习路径生成与技术题评价。
- Interview Agent：维护面试状态、决定追问。
- Project Agent：放到 P1，暂不实现。

这些 Agent 可以共用一个大模型 API。

与此同时，Career Orchestrator 先做简单的工作流编排，后续需要复杂任务协作时再升级。

另外，纯 Java 也可以通过 Spring AI 完成 RAG、Tool Calling 等能力。

因此双后端不是技术上的硬性要求，而是我们结合项目特点做出的架构选择。

## 七、最终确定的开发路线

根据我们已经确认的 P0 需求，第一阶段重点是六项核心能力，而不是实现所有规划功能。

我建议依次完成：

1. 工程基础：初始化三个工程，完成用户登录、数据库和 Java—Python 通信。
2. 岗位匹配链路：简历解析、JD 结构化、资格核验、岗位排序。
3. 能力画像：建立技能目录、能力证据模型与差距评估规则。
4. 动态八股文：题库建设、个性化出题、答案评价与学习计划。
5. 文字模拟面试：多轮追问、上下文管理、SSE 流式输出。
6. 闭环联调：面试与训练结果更新能力画像，并影响后续推荐。

## 我的最终建议

确定采用 Java＋Python 双后端。

使用 Spring Boot 模块化单体，而非 Spring Cloud 微服务。

Python 负责 Agent 和 AI 算法，Java 负责业务与数据。

优先打通 P0，暂不引入复杂基础设施。

从未来的大厂 AI 应用开发岗位来看，这套方案也有很好的技术覆盖面：既可以讲 Spring Boot 后端设计、系统接口和数据库，也可以讲 Agent 工作流、RAG、模型调用、评测以及跨服务协作。

下一步应该先做详细需求文档和数据库设计，再开始初始化项目。 这样后续用 Trae 辅助开发，也不会出现写到一半才发现各模块数据结构对不上的问题。
